# Releasing Grabbit

This is the single source of truth for releases. **AI agents must read this before any release task and follow it exactly. Do not invent anything.**

Releases are produced **only** by the `Release` GitHub Actions workflow (`.github/workflows/release.yml`, `workflow_dispatch`). No manual `gh release create`, no manual tag creation, no manual asset upload/renaming, no building release APKs outside the pipeline.

## Canonical release form

Every release MUST match this form. No exceptions, no per-release variations.

### Source of truth

- Version is read from committed `version.properties` (`MAJOR`, `MINOR`, `BUILD`).
- The app versionName inside every APK equals `MAJOR.MINOR.BUILD`.
- **No build mutates `version.properties`.** No auto-bump. `versionCode` = `MAJOR*1_000_000 + MINOR*1_000 + BUILD`, strictly increasing.
- Bump version in a separate `chore: bump version to X.Y.Z (versionCode N)` commit before releasing. Do not let the pipeline silently pick a different version.

### Tag

- `vX.Y.Z` — `v` + `MAJOR.MINOR.BUILD`. Lowercase `v`, semver `X.Y.Z`. No suffixes, no `-animation…`, no `-stable`, no extra words.
- The pipeline creates the tag. Fail if the tag or release already exists.
- `target` is `main` (default branch). Release from `main`.

### Title

- `Grabbit vX.Y.Z`. Exactly. Tag `vX.Y.Z`, title `Grabbit vX.Y.Z`. Nothing appended.

### Release type

- Not draft, not pre-release, unless the user explicitly says otherwise.
- `create_release` must be `true` to publish. `create_release=false` only builds artifacts.
- `device` / `abi` (adb install) are NOT release options. `abi` only picks which APK is installed on a connected device; it does NOT reduce published assets. `device` requires explicit user request.

### Assets (exactly these, nothing else)

| File | Notes |
|---|---|
| `grabbit-arm64-v8a-release.apk` | arm64-v8a |
| `grabbit-armeabi-v7a-release.apk` | armeabi-v7a |
| `grabbit-x86_64-release.apk` | x86_64 |
| `grabbit-universal-release.apk` | universal |
| `sha256sums.txt` | SHA-256 for every APK |

- All APKs signed, R8 minified + `shrinkResources`.
- No CI artifacts, no debug builds, no `.aab`, no extra outputs. No renaming outside the pipeline.
- `sha256sums.txt` lines: `<sha256>  grabbit-<abi>-release.apk`, sorted, one per APK. Verify `sha256sum -c sha256sums.txt`.

### Notes (exact structure, nothing else)

```
## What's Changed
<auto-generated from Conventional Commits / merged PRs since previous release — not hand-invented>
[GitHub may append `## New Contributors` and `**Full Changelog**: <link>`; left as emitted]

## Release assets
- `grabbit-arm64-v8a-release.apk` — arm64-v8a
- `grabbit-armeabi-v7a-release.apk` — armeabi-v7a
- `grabbit-x86_64-release.apk` — x86_64
- `grabbit-universal-release.apk` — universal (all supported ABIs)
- `sha256sums.txt` — SHA-256 checksums for every APK

All APKs are signed, R8-minified (`shrinkResources`). Verify with `sha256sum -c sha256sums.txt`.

## SHA-256
```
<contents of sha256sums.txt>
```
```

- Order and naming fixed. No `@`-mentions, no marketing, no handwritten fluff, no per-release heading variations. No `### SHA-256`, no `### APKs`, no `### What's new`, no hand-edits to generated sections. No `@`-mentions. Only `## Release assets` + `## SHA-256` are appended by the pipeline; `What's Changed` / `New Contributors` / `Full Changelog` come from GitHub.
- The `Release` pipeline always emits the canonical 5-asset form. **Existing older releases are normalized best-effort** (title, notes structure, `sha256sums.txt`); a missing `grabbit-universal-release.apk` / extra `sha256sums.txt` is NOT retroactively added to old releases, and original `What's new` changelog text is preserved. New releases must match the canonical form exactly.

### Commit style feeding notes

- Conventional Commits, imperative, first line < 72 chars: `feat:`, `fix`, `build`, `chore`, `refactor`, `docs`, `test`, `style`, `perf`. Version bumps: `chore: bump version to X.Y.Z (versionCode N)`. Release pipeline changes: `build: …`. No `@`-mentions in commits for release notes.

## Agent checklist (every release)

1. Read this file + `.github/workflows/release.yml` + `.github/workflows/checks.yml`.
2. `git status` clean for `version.properties`; confirm committed version; confirm intended `X.Y.Z`; confirm tag `vX.Y.Z` does not already exist (`gh release view`, `git ls-remote`).
3. `Checks` must pass (ktlint, detekt, Android lint, unit tests). Release `needs: checks`.
4. Run the **`Release`** workflow (`workflow_dispatch`) on `main`, `create_release=true`, `device=''`, default `abi`. Do not create a separate tag. Do not build/upload assets manually. Do not use `gh release create/edit` yourself.
5. **Wait** for the workflow to finish. Inspect run result. `gh release view vX.Y.Z --json tagName,name,body,assets`.
6. Verify exactly: tag `vX.Y.Z`, title `Grabbit vX.Y.Z`, not draft/pre-release, notes structure above, exactly the 5 assets, `sha256sums.txt` matches APKs, app `versionName == X.Y.Z`. Report URL + assets + any failed check. Never claim success on dispatch alone. Do not edit published releases afterward.
